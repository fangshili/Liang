Clicky Onboarding 完整研究报告

基于 farzaa/clicky 原仓库源码级分析

注意：开源版本是纯原生 macOS onboarding，无浏览器环节。但原生体验的动画设计、AI 集成、权限引导仍然非常值得借鉴。

1 整体架构

启动 → 自动判断是否弹出面板 → 用户点 Start → 触发 onboarding 演示 → 权限授予 → 完成。全程为原生 macOS 体验，没有 webview、没有浏览器、没有本地 HTTP server。

关键文件

入口

leanring_buddyApp.swift

app 启动后判断 hasCompletedOnboarding 和 allPermissionsGranted，任意未满足即自动弹出面板。面板是 borderless floating window —— 视觉上像网页但其实是 native。

面板 UI

CompanionPanelView.swift

权限状态列表（麦克风/辅助功能/语音识别）+ 可选邮箱输入 + Start 按钮。所有交互纯 SwiftUI。

核心引擎

CompanionManager.swift

onboarding 全生命周期管理：权限检测、触发演示、视频播放、Claude 截图分析、演示结束回调和状态流转。

动画渲染

OverlayWindow.swift

全屏透明叠加层：蓝色三角光标跟随、欢迎文字动画、导航气泡、贝塞尔飞行弧线。

设计系统

DesignSystem.swift

动画常量池：时长、缓动、曲线函数。button hover glow 的完整实现。

3 核心演示流程：triggerOnboarding()

这是 onboarding 最出彩的部分。不是填表、不是播放视频教程，而是一次 AI 实时分析你的屏幕 + 动画导航 的魔法时刻。

Step 1

全屏截图 → 发给 Claude Vision

CGWindowListCreateImage(.screenBounds) 抓全屏 → 转 base64 → POST 到 Claude API。prompt 要求 Claude 返回 JSON：{message: "...", x: 0.3, y: 0.4}（屏幕百分比坐标 + 气泡文字）。
同时播放 onboarding 视频（AVPlayer 后台静音加载）+ 背景音乐（ff.mp3 — Final Fantasy 的 Besaid 岛主题曲）。

Step 2

音乐结束 → 视频停止 → 创建蓝色三角光标

overlayWindow.showOverlay() 显示全屏透明 NSWindow，里面是 BlueCursorView：一个 22pt 蓝色三角形，60fps 平滑跟随鼠标（35pt 右偏移 + 25pt 下偏移）。

Step 3

欢迎文字动画："hey! i'm clicky"

蓝色三角旁显示文字气泡。逐字打印（30ms/字，easeIn 0.4s 气泡淡入），显示 2 秒后淡出。

Step 4

贝塞尔飞行弧线 → 指向 Claude 分析的元素

蓝色三角从当前鼠标位置沿贝塞尔曲线飞到 Claude 返回的屏幕坐标。飞行中旋转角度动态跟随切线方向。到达后显示导航气泡，逐字打印 Claude 的描述文字（每个字 30-60ms 随机延迟模拟"说话"节奏）。

Step 5

3 秒后飞回光标

指针在目标停留 3 秒，更新用户实际鼠标位置，飞回并恢复跟随模式。

Step 6

完成

UserDefaults.set(true, "hasCompletedOnboarding") — 下次启动不再弹面板。

4 动画技术细节

4.1 蓝色三角光标（BlueCursorView）

22pt 蓝色等边三角形，通过 TimelineView(.animation(minimumInterval: 1.0/60.0)) 以 60fps 读取 NSEvent.mouseLocation 并更新位置，形成平滑跟随效果。rotationEffect 控制箭头朝向。

组件
BlueCursorView — 22pt 三角形 + Shadow + 跟随偏移 (35, 25)
帧率
60fps (TimelineView + NSEvent.mouseLocation)
颜色
Color(red: 0.27, green: 0.62, blue: 0.98) ≡ #4582FA
旋转
rotationEffect(-35°) 默认，跟随时平滑过渡

4.2 贝塞尔飞行弧线

三角从当前位置到目标位置的路径不是直线，而是一条向上的二次贝塞尔曲线。60fps 逐帧更新位置，同时用 smoothstep 控制飞行进度（easeInEaseOut 效果），并在中点做 scale pulse（缩小 20%→恢复）。旋转角度沿切线方向动态计算。

路径
Quadratic bezier: control point 高于 start/end 中点 80-120pt
进度
smoothstep(t)，easeInEaseOut 效果
中点特效
scaleEffect 0.8→1.0（弹性缩小回弹）
旋转
实时计算切线角度 atan2(dx/dt, dy/dt)
时长
18fps × N 帧（根据距离动态）

4.5 主按钮 Hover Glow（DesignSystem）

// DesignSystem.swift — 按钮悬停发光动画
struct GlowButtonStyle: ButtonStyle {
    @State private var isHovering = false   // onHover
    @State private var glowPhase = 0.0

    var body {
        configuration.label
            .background(glowOverlay)   // radialGradient on hover
            .scaleEffect(isHovering ? 1.02 : 1.0)
            .animation(.easeOut(duration: 0.25), value: isHovering)
            .onHover { isHovering = $0 }
            .onAppear {
                // 2.5s 循环：发光透明度 + 半径同时呼吸
                withAnimation(.easeInOut(duration: 2.5).repeatForever()) {
                    glowPhase = 1.0
                }
            }
    }
}

5 权限引导流程

onboarding 面板不做自己的授权 UI，只负责三件事：显示状态、注册监听、跳转系统设置。授权框由 macOS 系统弹出。

麦克风

AVAudioSession.recordPermission

读状态 + AVAuthorizationStatus。未授权时面板显示 "Grant" 按钮 → openMicrophoneSettings()

辅助功能

AXIsProcessTrustedWithOptions

prompt:true 时弹出系统授权对话框。面板轮询检测状态变化。

语音识别

SFSpeechRecognizer.authorizationStatus

读取 iOS-style API 状态，不需要系统设置跳转。

屏幕录制

CGPreflightScreenCaptureAccess

不在 onboarding 面板里出现。首次截图时才检测并跳转设置（懒加载）。

设计原则

面板只做"状态展示 + 跳转入口"，把授权交互完全交给 macOS 原生控件。这保证了用户看到的是 Apple 的标准权限对话框（统一 UI），而不是自己拼凑的可疑授权 UI。

6 AI 集成：Claude 屏幕分析

// CompanionManager.swift — triggerOnboarding() 核心逻辑
// 1. 全屏截图
let image = CGWindowListCreateImage(
    .infinite, .optionOnScreenOnly,
    0, .bestResolution
)
let base64 = image?.base64()

// 2. 发给 Claude (type: image + text)
let response = await sendToClaude(messages: [
    { type: "image", source: base64 },
    { type: "text", text: """
        Pick ONE thing on this screen and point to it like you're showing 
        a friend something cool. Reply with JSON: {message, x, y} where 
        x/y are 0-1 percentages. Message is a short fun phrase.
    """}
])

// 3. 解析 → 导航到目标坐标 + 显示气泡
let targetScreenX = response.x * screenWidth
let targetScreenY = response.y * screenHeight
navigateTo(x: targetScreenX, y: targetScreenY, message: response.message)

这个流程让 onboarding 变成 "AI 对着你的屏幕说话"，而不是千篇一律的教程视频。每次看到的演示内容都不同，因为它分析的是用户当前的真实桌面。

Smoothstep 函数

// DesignSystem.swift — 平滑步进曲线
static func smoothstep(_ t: Double) -> Double {
    let clamped = max(0, min(1, t))
    return clamped * clamped * (3 - 2 * clamped)
}
// 用于贝塞尔飞行弧线的进度插值：启停平滑，中间线性

可借鉴点

P2 — 主按钮 hover glow

2.5s 循环的 radialGradient 呼吸 + hover 1.02x scale。你现有的 button styles 都很平，加上这个门槛极低（~10 行），但质感提升明显。

P3 — smoothstep 缓动函数

你当前动画全用系统 easeInEaseOut。smoothstep 在飞行/导航类路径动画中比系统 curve 更自然（启停平滑，中间线性）。DesignSystem 里 4 行代码即可复用。

P3 — 欢迎文字逐字打印

30-60ms 随机延迟模拟"说话"节奏，比一口气显示整段文字生动得多。适合首次启动的欢迎语或状态切换的提示文案。

10 总结

开源版的 truth

两个开源仓库（dabit3/heyclicky-clone 和 farzaa/clicky）都没有浏览器 onboarding。你体验过的浏览器 → macOS 无缝衔接大概率是 clicky 的商业发布版本独有功能，可能通过以下方式实现：

  • 网站端完成配置（权限勾选 + 邮箱）→ 生成 deep link (clicky://setup?token=xxx) → app 收到 URL scheme 拉起并写入本地
  • 或者 app 启动时在本地起一个 HTTP server，浏览器打开 localhost:PORT 完成配置
  • 这两种模式在开源代码中都 404

如果你确实想复刻"浏览器配置 → 写入 macOS 应用"这条路径，方案很明确：CFBundleURLTypes 注册 custom scheme + application(_:open:) handler。但这需要额外开发一个 web 前端。

但即使没有浏览器环节，开源版的 onboarding 依然有大量值得借鉴的细节
